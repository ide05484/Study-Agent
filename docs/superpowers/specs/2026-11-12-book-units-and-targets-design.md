- 날짜: 2026-11-12
- 상태: 승인(2026-11-12). 구현 계획 [2026-11-12-book-units-and-targets.md](../plans/2026-11-12-book-units-and-targets.md)

## 목적

기본서 + 인강처럼 실제로 공부하는 단위로 교재를 등록하고, 회독마다 "언제까지"를 정하면 계획이 그 날짜에 맞게 나뉜다. 밀린 분량은 따라잡게 하되, 시험 마지막 주에는 분량을 늘려 수험생을 불안하게 만들지 않는다.

## 결정 (사용자, 2026-11-12)

| 항목 | 결정 |
|---|---|
| 단위 | 쪽은 없앤다. **Day · 챕터 · 회차** 세 가지 |

## 범위

이 설계(묶음 A)에 넣는 것: DB 구조, 나누는 규칙(`_shared/plan.ts`), `plan-generator`, 공부 설정 화면(교재 폼·행), 목표일 지남 모달, 공용 `ChipGroup`·`Modal`·확인/알림, 계획 미리보기와 Mock 데이터, 관련 문서.

나중에 따로 설계하는 것:

| 묶음 | 내용 | 시기 |
|---|---|---|
| B | 채팅 화면의 오늘의 분량을 입력창 위 떠 있는 버튼 → 큰 모달로. 왼쪽 체크박스로 완료 표시(진도 반영) | A 다음 (LLM 없이 가능) |
| C | 채팅으로 "나 ~ 완료했어"를 LLM이 이해해 반영. 오늘 분량이 아닌 공부도 다른 계획에 반영 | 1단계 채팅 Task 3~7에 요구사항으로 추가 |
| D | 시험 한 달 전부터 응원·위로·자신감을 주는 메시지로 채팅 시작 | 채팅·알림 단계에 요구사항으로 추가 |

## 1. 데이터 구조

새 마이그레이션 하나에서 바꾼다. 이미 반영된 마이그레이션 파일은 고치지 않는다. 운영 DB에는 2단계 마이그레이션(`20261110042741`)부터 아직 배포되지 않았다(`main`은 초기 커밋뿐).

| 대상 | 바꾸는 것 |
|---|---|
| `public.book_unit` | `page`·`day` → `day`·`chapter`·`session`. 새 enum을 만들어 칸을 옮기고 옛 enum을 지운다. 기존 `page` 행은 `session`으로 옮긴다(숫자는 그대로, 개발 DB Mock은 다시 넣는다). 기본값은 `session` |
| `books` | `total_pages` → `total_units`, `current_page` → `current_unit`. 제약 `books_current_page_max` → `books_current_unit_max` |
| `books.daily_amount` | 이름 그대로. 뜻을 "하루 고정"에서 **"하루 최소"**로 바꾼다. 컬럼 주석으로 남긴다 |
| `books.round_targets` | 새 칸 `date[] not null default '{}'`. n번째 값이 n회독 목표일, null은 목표일 없음. check: `cardinality(round_targets) <= target_rounds` |
| `daily_tasks` | `start_page`·`end_page` → `start_unit`·`end_unit` |
| `study_logs` | `start_page`·`end_page` → `start_unit`·`end_unit` |
| `replace_daily_tasks` | 새 칸 이름으로 `create or replace`(시그니처·권한·잠금은 그대로) |

목표일의 순서(앞 회독보다 늦거나 같음)와 시험일 이전인지는 DB가 아니라 화면 입력에서 막는다. 시험일을 나중에 앞당기면 시험일 이후가 된 목표일이 생길 수 있어서, 규칙(2장)이 시험 전날로 줄여 쓴다.

타입: `npm run gen:types`로 `database.ts`를 다시 만들고 `interfaces/study.ts`(`Book`, `NewBook`, `BookProgress` → 계획 설정까지 담는 이름으로), `interfaces/plan.ts`, Backend `PlanBook`·`PlannedTask`를 맞춘다.

## 2. 나누는 규칙 (`_shared/plan.ts`)

`plan.ts`는 계속 아무것도 import하지 않는 순수 함수다. DB에서만 알 수 있는 값(마지막 주 상한)은 호출자가 넘긴다.

### 입력

- 교재: `total_units`(U), `current_round`, `current_unit`, `target_rounds`(R), `round_targets`, `daily_amount`(최소 분량 m, 없으면 null)
- `days`: 오늘(0일째)부터 시험 전날까지의 공부 날 수
- 마지막 주 상한 `lastWeekCap`: 이 교재의 D-8 하루 분량. 오늘이 D-7 이후이고 D-8 계획이 있을 때만 숫자, 아니면 null
- 회독별 목표일: 호출자가 날짜를 "오늘부터 며칠째"로 바꿔 넘긴다(`targetDays[r]`, 목표일 없으면 null). `plan.ts`는 날짜 계산을 하지 않는다

### 기한 구간

1. 회독 r(지금 회독 ~ R)에 목표일이 있으면 "누적 r × U까지, targetDays[r]일째까지"라는 기한을 만든다.
2. 목표일이 시험 전날보다 늦으면 시험 전날로 줄인다.
3. 목표일이 오늘보다 이르고(지남) 그 회독이 안 끝났으면 기한을 오늘 + 14일(최대 시험 전날)로 본다. 화면 모달이 보통 그 전에 새 날짜를 저장하므로 이 처리는 저장 전 재분배를 위한 안전장치다.
4. 앞 기한보다 이른 기한은 앞 기한으로 올린다(순서 보장).
5. 마지막 기한은 언제나 "누적 R × U까지, 시험 전날까지"다. 목표일이 없는 회독은 다음 기한 구간에 합쳐진다.

### 하루 분량 (날마다 다시 계산)

- 필요 분량: 구간을 시작한 날 위치 p₀, 구간 분량 A, 구간 날 수 L이면 구간의 k번째 날(0부터)까지 누적 위치는 p₀ + floor((k + 1) × A ÷ L)이고, 그날 필요 분량은 그 위치까지 남은 만큼이다. 기한 당일에 구간이 끝난다. 예: 10회를 4일 → 2·3·2·3. 목표일·최소 분량이 없으면 지금 결과와 같다.
- 최소 분량이나 마지막 주 상한 때문에 위치가 고른 누적 위치에서 벗어나도 구간 안에서는 다시 계산하지 않는다(앞서가면 다음 날 필요 분량이 줄고, 밀리면 늘어 따라잡는다). 다음 구간은 그 구간에 들어선 날의 위치에서 새로 시작한다(p₀ = 그때 위치).
- 하루 분량 = max(필요 분량, m). m 때문에 구간을 일찍 끝내면 남은 분량은 바로 다음 구간(다음 회독)으로 이어진다.
- D-7 ~ 시험 전날(시험 전날부터 거꾸로 7일)은 하루 분량을 `lastWeekCap` 이하로 줄인다(상한이 있을 때). 그래서 시험 전날까지 다 끝나지 않을 수 있고, 남은 분량은 계획에 넣지 않는다.
- 분량이 0인 날은 줄을 만들지 않는다. 하루 범위가 회독 경계를 넘으면 지금처럼 회독마다 한 줄로 나누고 `round`를 남긴다.

### `plan-generator`

- 오늘이 D-7 이후면 교재별로 D-8(`exam_date - 8`)의 `daily_tasks` 분량 합(`end_unit - start_unit + 1`)을 읽어 `lastWeekCap`으로 넘긴다. D-8 계획이 없는 교재는 null(상한 없이 고르게).
- 목표일을 "오늘부터 며칠째"로 바꿔 넘긴다.
- 그 밖의 흐름(`replace_daily_tasks`, 응답 `PlanResponse`)은 그대로다.

### 테스트 (Deno, `plan_test.ts`)

목표일 없음은 지금 결과와 같음 / 1회독 목표일 / 목표일 없는 회독이 다음 구간에 합쳐짐 / m이 필요 분량보다 큼(일찍 끝나고 다음 회독으로) / 지난 목표일(오늘 + 14일) / 시험일 이후 목표일 / 순서가 뒤집힌 목표일 / 회독 경계를 넘는 날 / 마지막 주 상한(남는 분량) / 상한 null / 이미 끝난 교재 / `completedUnits` 새 칸 이름.

## 3. 화면

### 공용 컴포넌트 (디자인 시스템, `/ui` 카탈로그와 DESIGN.md에 추가)

- **ChipGroup**: 짧은 선택지(2~4개) 하나 고르기. `role="radiogroup"`, 칩마다 `role="radio"`, 높이 44px, 고른 칩은 `accent-soft` 바탕 + `accent` 테두리 + 굵은 글자, 나머지는 `line` 테두리 + `muted` 글자, 화살표로 이동. 줄이 넘치면 다음 줄로 감싼다. 앱 칸 안에만 그려져 PC에서 잘리지 않는다.
- **Modal**: 화면 가운데 창. 네이티브 `<dialog>`(`showModal`)로 포커스 가두기·Esc 닫기를 브라우저에 맡긴다. 바깥은 `scrim`, 창은 `rounded-2xl border-line bg-bg`, 팝업 그림자 예외(`shadow-lg`)를 따른다. props: `open`, `title`, `onClose`, `children`, `actions`(아래 버튼 줄). 폭은 앱 칸(480px) - 좌우 16px.
- **확인·알림**: Modal 위에 만든다. 앱 어디서나 `const confirm = useConfirm()` → `await confirm({ title, message, confirmLabel, tone })`(`Promise<boolean>`), `useAlert()` → `await alert({ title, message })`. 제공자는 `AppLayout`에 하나 둔다. `tone: 'danger'`면 확인 버튼이 위험 표시. 지금의 `window.confirm` 두 곳(교재 삭제, 선택 삭제)을 바꾼다.

### 공부 설정: 교재 추가 폼

순서: 과목(ChipGroup 4개) → 교재명 → 단위(ChipGroup `Day`·`챕터`·`회차`) → 총량(`총 120회`) → 목표 회독(1~10) → 회독별 목표일 → 하루 최소 분량(선택).

- 회독별 목표일: 목표 회독 수만큼 `1회독 목표일 [DatePicker]` 줄이 생긴다. 모두 비워도 된다. 앞 회독 목표일보다 이른 날, 오늘 이전, 시험일 이후는 고를 수 없다.
- 하루 최소 분량: 비우면 목표일(또는 시험 전날)까지 고르게.
- 시험 점수 폼의 구분(모의고사/실제 시험)도 ChipGroup으로 바꾼다. 화면에 남는 `<select>`는 없게 한다.

### 공부 설정: ⋮ → 수정

진도(현재 회독, 어디까지)와 함께 목표 회독, 회독별 목표일, 하루 최소 분량을 고친다. 목표 회독을 줄이면 넘치는 목표일은 지운다. 저장하면 계획을 다시 나눈다.

### 교재 행

```
기본서            2/3회독 45/120회  ⋮
                  2회독 목표 12월 31일
쉬운국어          12/30회           ⋮
                  1회독 목표일 지남
```

- 표기: `Day 3–4`, `3–4챕터`, `12–14회`. 진도는 목표 1회독이면 `12/30회`·`Day 12/60`·`3/20챕터`, 2회독 이상이면 앞에 `2/3회독`.
- 지금 회독에 목표일이 있으면 행 아래에 `muted`로 작게. 지났고 그 회독을 못 끝냈으면 `목표일 지남`(`danger`).

### 목표일 지남 모달

- 언제: 로그인 뒤 앱을 열 때(`AppLayout`), 지금 회독의 목표일이 오늘보다 이르고 그 회독을 못 끝낸 교재가 있으면.
- 내용: 제목 `목표일이 지났어요`, 문구 `다음 목표일을 정하면 계획을 다시 나눠 드려요.`, 교재·회독마다 한 줄(`국어 기본서 · 1회독` + DatePicker, 기본값 오늘 + 14일, 최대 시험 전날).
- `저장`: 고른 날짜를 `round_targets`에 저장하고 계획을 한 번 다시 나눈다. `나중에`: 기본값(오늘 + 14일)을 저장한다. 그래서 같은 모달이 다시 뜨지 않는다.
- 시험일이 없으면 띄우지 않는다.

### 화면 문구

해요체, coach-tone.md를 따른다. 마지막 주에 남는 분량이 있어도 화면·안내에 재촉하는 문구를 쓰지 않는다.

1. 목표일이 없는 교재의 계획이 지금과 같다(회귀 없음).
