## 0. 기반: 채팅보다 먼저 필요한 것

채팅은 로그인한 사용자의 데이터(RLS)와 OpenAI 키가 있어야 동작한다. 지금은 둘 다 없어서 1단계 계획 안에 함께 넣었다.

- 개발용 Supabase 프로젝트에 마이그레이션 반영(`db push`), 함수 비밀 값(`OPENAI_API_KEY`) 등록
- **카카오 로그인**: 처음부터 카카오로만 로그인한다. 카카오 앱 키는 사용자가 나중에 발급해 Supabase 대시보드에 넣는다. 키가 오기 전에는 코드와 설정 문서만 만들고, `chat` 함수는 화면에 없는 검증용 테스트 계정으로 확인한다.
- 이메일 동의항목(`account_email`)은 비즈 앱만 받을 수 있어 받지 않고, Supabase의 "Allow users without an email"을 켠다.
- 카카오톡 메시지 발송에 필요한 `talk_message` 동의와 카카오 토큰 보관은 알림 단계에서 추가한다(추가 동의를 받는 방식).

## 1. 채팅 연결

**목표**: 오늘 채팅방에서 보낸 메시지에 코치가 답하고, 공부한 분량을 말하면 기록·진도에 반영된다.

- 처리하는 의도: 학습 기록 보고, 공부법·고민 질문, 사용법 질문
- 일정(분량 재배분)과 교재 추가는 의도만 알아듣고, 아직 지원하지 않는다고 안내한다(각각 "이후", 2단계)
- **완료 기준**: "보건행정 기본서 30~70p, 기출 20문제 중 5개 틀림"을 보내면 `study_logs`가 저장되고, 교재 진도와 오늘의 분량 상태가 바뀌고, 코치가 진도율을 넣어 답한다.

## 1.5 디자인 시스템 정리

2·3단계에서 입력 폼과 대시보드 화면이 늘어나기 전에, 지금의 토큰과 클래스 묶음을 컴포넌트로 정리한다.

- `components/ui/classes.ts`의 문자열 묶음을 `Button`, `TextField`, `Select`, `Section`, `Disclosure`, `Notice` 같은 컴포넌트로 바꾼다. 변형은 지금 말풍선처럼 `Record<variant, className>` 매핑으로 둔다(새 라이브러리 없음).
- 개발 모드에서만 열리는 `/ui` 화면에 모든 컴포넌트와 색상 토큰을 라이트·다크로 모아 보여 준다(Storybook 대신 쓰는 카탈로그).
- DESIGN.md의 "컴포넌트 메모"를 컴포넌트 목록과 사용 규칙으로 바꾼다.
- **완료 기준**: 페이지 파일에 버튼·입력 필드의 Tailwind 클래스가 직접 남지 않고, `/ui`에서 모든 컴포넌트를 확인할 수 있다.

## 2. 공부 데이터 채우기

**목표**: 실제 수험 데이터를 앱에 넣을 길을 모두 열고 채운 뒤, D-Day까지의 목표 공부량에 맞춰 계획을 다시 나눈다.

1단계 Task 1 Step 4.5에서 해커스 교재 8권(과목·제목·총 페이지)을 먼저 넣는다(2026-10-30). 이 단계에서는 그 교재에 공부한 범위·회독 목표를 채운다.

넣을 데이터 (사용자 확인, 2026-10-27):
- 지금 가진 교재와 교재별 분량(총 페이지)
- 교재별로 지금까지 공부한 범위
- 지금까지 본 모의고사 점수와 실제 시험 점수(지방직 공무원 시험 2회)
- D-Day까지 목표 공부량: 가진 교재는 모두 1회독, 기본서는 N회독

할 일:
- **회독 목표**: 지금 스키마는 교재당 1회독(`current_page` → `total_pages`)만 표현한다. `books`에 목표 회독 수와 현재 회독을 담는 새 마이그레이션을 추가하고, `plan-generator`가 남은 회독까지 포함해 분배하게 바꾼다. 1단계에서 초기 스키마를 `db push`하므로 초기 스키마 수정이 아니라 새 마이그레이션으로 한다.
- **실제 시험 점수**: `mock_exams`에 모의고사와 실제 시험을 구분하는 값을 둔다. 대시보드·코치가 둘을 다르게 다룬다("지방직 때보다 ○점 올랐어요").
- 채팅으로 교재 추가(SERVICE_FLOW 6): `plan-generator`의 분배 로직을 `_shared/plan.ts`로 옮겨 `chat`에서도 재분배한다.
- 모의고사·시험 점수 입력: `mock_exams`, `mock_exam_scores`에 넣을 경로가 아직 없다.
- 기록하지 않은 날 확인(SERVICE_FLOW 5.1): "어제 공부한 거" 같은 지난 날짜 기록.
- 실제 데이터를 입력하고 계획을 다시 나눈다.
- **먼저 정할 것**: 점수를 채팅으로 받을지 공부 설정 화면 폼으로 받을지(또는 둘 다), 기본서를 어떻게 구분할지(교재 종류 값 또는 교재별 목표 회독 수만), 회독 중인 교재의 "지금까지 공부한 범위"를 어떻게 입력받을지, 처음 한 번 많은 데이터를 넣는 방법(화면 입력 또는 정리한 표를 한 번에 넣는 스크립트).

## 2.1 공부법 채우기

**목표**: [docs/study-methods](../../study-methods/README.md)의 내용이 코치 답변과 공부 설정 화면에 쓰인다.

- 사용자가 과목 파일의 ✏️ 표시를 채운다(사용자 작업).
- 문서 → 앱 반영: 스크립트로 문서를 TS 상수로 만들어 `chat` 프롬프트와 프론트엔드에서 함께 쓴다.
- 과목별 메모 저장 테이블(`study_method_memos`, 사용자·과목당 1행)을 추가하고, 메모를 코치 컨텍스트에 넣는다.
- **완료 기준**: 공부 설정의 "준비 중"이 실제 공부법으로 바뀌고, 메모를 저장하면 코치가 답변에 참고한다.
