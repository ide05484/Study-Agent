## 0. 기반: 채팅보다 먼저 필요한 것

채팅은 로그인한 사용자의 데이터(RLS)와 OpenAI 키가 있어야 동작한다. 지금은 둘 다 없어서 1단계 계획 안에 함께 넣었다.

- 개발용 Supabase 프로젝트에 마이그레이션 반영(`db push`), 함수 비밀 값(`OPENAI_API_KEY`) 등록
- **카카오 로그인**: 처음부터 카카오로만 로그인한다. 카카오 앱 키는 사용자가 나중에 발급해 Supabase 대시보드에 넣는다. 키가 오기 전에는 코드와 설정 문서만 만들고, `chat` 함수는 화면에 없는 검증용 테스트 계정으로 확인한다.
- 이메일은 쓰지 않고 Supabase의 "Allow users without an email"을 켠다. 다만 Supabase가 `account_email`을 항상 요청하므로, 카카오 앱을 개인 개발자 비즈 앱으로 전환하고 이메일 동의항목을 선택 동의로 둔다(2026-11-06 확인).
- 카카오톡 메시지 발송에 필요한 `talk_message` 동의와 카카오 토큰 보관은 알림 단계에서 추가한다(추가 동의를 받는 방식).

## 1. 채팅 연결

**목표**: 오늘 채팅방에서 보낸 메시지에 코치가 답하고, 공부한 분량을 말하면 기록·진도에 반영된다.

- 처리하는 의도: 학습 기록 보고, 공부법·고민 질문, 사용법 질문
- 일정(분량 재배분)과 교재 추가는 의도만 알아듣고, 아직 지원하지 않는다고 안내한다(각각 "이후", 2단계)
- **완료 기준**: "보건행정 기본서 30~70p, 기출 20문제 중 5개 틀림"을 보내면 `study_logs`가 저장되고, 교재 진도와 오늘의 분량 상태가 바뀌고, 코치가 진도율을 넣어 답한다.

## 1.5 디자인 시스템 정리

2·3단계에서 입력 폼과 대시보드 화면이 늘어나기 전에, 지금의 토큰과 클래스 묶음을 컴포넌트로 정리한다.

- `components/ui/classes.ts`의 문자열 묶음을 `Button`, `TextField`, `Select`, `Section`, `Disclosure`, `Notice` 같은 컴포넌트로 바꾼다. 변형은 지금 말풍선처럼 `Record<variant, className>` 매핑으로 둔다(새 라이브러리 없음).
- 개발 모드에서만 열리는 `/ui` 화면에 모든 컴포넌트와 색상 토큰을 라이트·다크로 모아 보여 준다(Storybook 대신 쓰는 카탈로그).
- DESIGN.md의 "컴포넌트 메모"를 컴포넌트 목록과 사용 규칙으로 바꾼다.
- **완료 기준**: 페이지 파일에 버튼·입력 필드의 Tailwind 클래스가 직접 남지 않고, `/ui`에서 모든 컴포넌트를 확인할 수 있다.

## 2. 공부 데이터 채우기

**목표**: 실제 수험 데이터를 앱에 넣을 길을 모두 열고 채운 뒤, D-Day까지의 목표 공부량에 맞춰 계획을 다시 나눈다.

1단계 Task 1 Step 4.5에서 해커스 교재 8권(과목·제목·총 페이지)을 먼저 넣는다(2026-10-30). 이 단계에서는 그 교재에 공부한 범위·회독 목표를 채운다.

넣을 데이터 (사용자 확인, 2026-10-27):
- 지금 가진 교재와 교재별 분량(총 페이지)
- 교재별로 지금까지 공부한 범위
- 지금까지 본 모의고사 점수와 실제 시험 점수(지방직 공무원 시험 2회)
- D-Day까지 목표 공부량: 가진 교재는 모두 1회독, 기본서는 N회독

할 일:
- **회독 목표**: 지금 스키마는 교재당 1회독(`current_page` → `total_pages`)만 표현한다. `books`에 목표 회독 수와 현재 회독을 담는 새 마이그레이션을 추가하고, `plan-generator`가 남은 회독까지 포함해 분배하게 바꾼다. 1단계에서 초기 스키마를 `db push`하므로 초기 스키마 수정이 아니라 새 마이그레이션으로 한다.
- **실제 시험 점수**: `mock_exams`에 모의고사와 실제 시험을 구분하는 값을 둔다. 대시보드·코치가 둘을 다르게 다룬다("지방직 때보다 ○점 올랐어요").
- 채팅으로 교재 추가(SERVICE_FLOW 6): `plan-generator`의 분배 로직을 `_shared/plan.ts`로 옮겨 `chat`에서도 재분배한다.
- 모의고사·시험 점수 입력: `mock_exams`, `mock_exam_scores`에 넣을 경로가 아직 없다.
- 기록하지 않은 날 확인(SERVICE_FLOW 5.1): "어제 공부한 거" 같은 지난 날짜 기록.
- 실제 데이터를 입력하고 계획을 다시 나눈다.
- **정한 것 (2026-11-10)**: 점수는 공부 설정 화면 폼으로 받고(채팅은 Task 3~7 뒤), 기본서는 교재별 목표 회독 수로만 구분한다(기본서 3회독, 나머지 1회독). 진도는 "몇 회독째 + 몇 쪽까지"로 받는다. 처음 데이터는 Mock 데이터 스크립트로 넣고, 실제 사용자 데이터는 나중에 화면으로 넣는다. 단어장처럼 하루 고정 분량(Day 단위) 교재도 다룬다. 상세는 [2단계 계획](2026-11-10-study-data.md).

## 2.1 공부법 채우기

**목표**: [docs/study-methods](../../study-methods/README.md)의 내용이 코치 답변과 공부 설정 화면에 쓰인다.

- 조사 문서로 과목 4개·멘탈관리·시간관리 정리본을 쓰고, `npm run methods:migration`이 만든 마이그레이션으로 DB `study_methods`에 넣는다.
- 메모 칸 대신 채팅에서 말한 **잘 맞은 방법**을 `study_tips`에 바로 저장하고, 탭에서 보고 지운다(2026-11-18 사용자 결정).
- 코치는 질문에 답할 때 그 과목 공부법과 잘 맞은 방법, 필요하면 멘탈·시간관리를 근거로 쓴다. 점수 하락·지침·불안에는 "힘들 때 말하는 방식"을 따른다.
- **완료 기준**: 공부 설정에 공부법이 보이고, 코치가 공부법과 잘 맞은 방법을 근거로 답한다. 상세는 [2.1단계 계획](2026-11-18-study-methods.md).

## 2.2 채팅으로 교재 추가

**목표**: 채팅 한두 마디로 교재를 등록하고, 시험일까지 분량이 바로 다시 나뉜다(2026-11-23 피드백 2번).

- 빠진 정보(과목·교재명·단위·총량)는 다시 묻고, 다 모이면 요약과 응/아니 칩으로 확인받은 뒤 저장한다. 칩 처리에는 GPT를 쓰지 않는다.
- 받아 둔 교재는 코치 메시지(`chat_messages.action`)에 붙이고, 재분배는 `plan-generator`와 공용 모듈로 서버에서 한다.
- **완료 기준**: 채팅으로 교재를 추가하면 공부 설정과 오늘의 분량에 바로 보인다. 상세는 [설계](../specs/2026-11-23-chat-book-add-design.md).

## 2.3 채팅 다듬기 (`fix/chat`)

2.2를 병합한 뒤 `fix/chat` 브랜치에서 한다(2026-11-23 사용자 결정). 항목별 출처·코드 위치·Minor 처리 표는 [History](../../../History/2026-11-23-채팅-다듬기.md)에 있다.

**결과(2026-11-24)**: 아래 항목을 모두 구현하고 개발 프로젝트에서 확인했다. 하루 첫 메시지는 브라우저 확인에서 느리다는 지적으로 오늘 분량을 빼고 화면이 바로 띄우는 방식으로 바꿨다(이 방식은 아직 브라우저 확인 전). 시험일 지난 계정의 교재 확인 문구도 확인을 미뤘다. 아래는 시작 때 적은 범위다.

- **하루 첫 메시지(A)**: 지금은 "오늘 하루도 화이팅! 합격까지 달려봐요"(`WELCOME_MESSAGE`) 한 줄뿐이다(2026-11-23 피드백 1번). 오늘 분량 등으로 채운다. 아침 알림(`daily-briefing`) 계획과 합쳐 정한다.
- **답을 기다리는 동안 또 보낸 메시지(B)**: 앞 메시지의 답을 받기 전에 메시지를 또 보내면, 앞 메시지에는 답하지 않고 마지막 메시지에만 답한다(2026-11-23 사용자 요청). 지금은 답을 기다리는 동안 보내기 버튼이 막혀 있다.
- **오늘의 분량 버튼 가림(D)**: 마지막 말풍선을 가려 한 번 더 스크롤해야 한다. 목록 아래 여백(`pb-16`)이 있는데도 2026-11-23에 아직 재현된다.
- **예/아니오 칩(E)**: 코치가 "오늘은 마무리할까요?"처럼 예/아니오로 끝나면 네/아니오 칩을 보인다. 2.2의 `action` 칸과 `ConfirmChips`를 다시 쓴다.
- **교재 추가 초안(H·I)**: 다른 교재를 말하면 이전 값이 넘어오는 문제, 잘못된 순공시간이 오면 초안이 버려지는 문제.
- **2.2 Minor**: 시험일 지남 문구, 메시지 정렬, 단위 목록 합치기, 요청 파싱 분리, 테스트 보강 등(History 표).
- **먼저 정할 것**: 첫 메시지에 넣을 내용과 알림과의 관계. 답하지 않는 앞 메시지를 채팅에 남길지, 남긴 메시지의 공부 기록·순공시간은 저장할지. 버튼 가림의 원인. 예/아니오 칩을 무엇으로 판단할지.

## 다음 날 첫 메시지에서 어제 기록 묻기

2026-11-24 사용자 요청. 마무리 칩에서 순공시간을 물었는데 답하지 않고 자러 가면("이제 잘게") 그날 순공시간이 비는데, 그날은 다시 묻지 않고 **다음 날 첫 메시지가 어제 기록을 물으며 시작**한다. 2.3의 하루 첫 메시지(화면이 바로 만드는 `Frontend/src/libs/welcome.ts`)에 분기를 더한다.

- **분기점** (어제 = 공부 날짜 기준 전날, 새벽 2시 경계):
  1. 어제 공부 흔적(끝낸 분량·채팅 학습 기록)은 있는데 순공시간이 없음 → "어제 순공시간을 적지 않았어요. 어제 분량 3개 중 2개 끝내셨는데, 순공시간은 얼마나 됐나요?" + `study_time_ask`(어제 날짜).
  2. 어제 공부 흔적도 순공시간도 없음 → [SERVICE_FLOW 5.1](../../../SERVICE_FLOW.md#51-기록하지-않은-날-확인)의 "어제는 공부하지 않으신 것 같아요. 혹시 공부하셨다면…" 확인.
  3. 어제 순공시간이 있음 → 지금 첫 메시지(시험까지 남은 날 + 응원 + 공부 가능 시간 질문).
  - 1·2가 오늘 질문과 겹치면 어제 질문을 먼저 하고, 공부 가능 시간 질문은 그 답 뒤로 미룬다(한 메시지에 질문 하나).
- **정할 것**: `study_time_ask`에 날짜(어제)를 담아 "4시간"을 어제 순공시간으로 저장하는 방법(지금은 오늘로만 읽는다). 2번의 답("어제 국어 2챕터 했어")은 지난 날짜 학습 기록(F)이 있어야 저장된다. 어제 흔적을 첫 메시지 전에 읽어도 빠르게 뜨도록 조회는 화면에서 DB를 직접 한두 번(2.3 첫 메시지 원칙: 서버·GPT를 거치지 않는다).
- 아침 알림을 만들면 같은 분기를 알림 메시지가 이어받는다.
