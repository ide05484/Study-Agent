# 보건직 과목별 공부법

이 앱의 코치가 과목별 공부법을 제안할 때 따르는 기준이다. 이 폴더가 **앱 공부법 내용의 원본**이다. 내용 파일은 DB `study_methods`로 옮겨져 공부 설정 "과목별 공부법" 탭과 코치 답변(`chat`)에 쓰인다(아래 "앱 반영").

## 파일

| 파일 | 내용 | DB `topic` | 화면 |
|---|---|---|---|
| [korean.md](korean.md) | 국어 | `korean` | 보임 |
| [english.md](english.md) | 영어 | `english` | 보임 |
| [public-health.md](public-health.md) | 공중보건 | `public_health` | 보임 |
| [health-admin.md](health-admin.md) | 보건행정 | `health_admin` | 보임 |
| [mental.md](mental.md) | 멘탈관리(힘들 때) | `mental` | 보임 |
| [time.md](time.md) | 시간관리, 학습 단계, 공통 원칙(회독·기출 우선·오답 관리) | `time` | 안 보임(코치만) |
| [research/](research/2026-11-보건직-과목별-공부법.md) | 조사 문서 원문. [확인]/[추정]/[미확인]과 출처의 근거 | – | – |

해당 과목 파일만 읽는다. 여러 과목의 균형(시간 배분)이나 학습 단계를 다룰 때는 `time.md`를 본다.

## 공부법을 제안하는 순서

1. **과목과 문제를 특정한다.** 어떤 과목인지, 어떤 어려움인지(암기, 이해, 독해 속도, 시간 부족, 실수, 성적 정체) 확인한다. 모호하면 묻는다. 막연한 "열심히 하세요"보다 문제에 맞는 처방 하나가 훨씬 도움이 된다.
2. **데이터로 근거를 찾는다.** `mock_exam_scores`(과목별 점수 추이), `study_logs`(최근 공부량·틀린 문제 수), `books`·`daily_tasks`(진도·밀린 분량)를 본다.
3. **학습 단계를 판단한다.** 남은 기간과 진도로 지금이 어느 단계인지 본다([time.md](time.md) "학습 단계"). 단계마다 맞는 공부법이 다르다.
4. **처방은 1~2개만, 바로 할 수 있게.** 과목 파일의 "고민별 처방"에서 고르고, 오늘 분량과 연결한다.
5. **말투는 [코치 톤](../coach/coach-tone.md)을 따른다.** 공감 → 근거 있는 칭찬 → 처방 → 다음 행동 질문.

## 앱 반영

이 폴더의 내용 파일은 DB 테이블 `study_methods`로 옮겨진다. 옮기는 스크립트가 읽을 수 있도록 형식을 지킨다.

- `topic` 값: `korean`, `english`, `public_health`, `health_admin`, `mental`, `time`. 과목 4개는 `public.subject` enum과 같은 문자열. 라벨: 과목은 `SUBJECT_LABELS`, `mental` → `멘탈관리`, `time` → `시간관리`.
- 내용 파일: `korean.md`, `english.md`, `public-health.md`, `health-admin.md`, `mental.md`, `time.md`(모두 `docs/study-methods/`). 형식: `# 제목` 한 줄, `## 소제목` 섹션, 섹션 본문은 `- ` 목록 또는 두 칸 표 하나만, 꾸밈은 `**`·`==`만, 형광펜 파일당 최대 3곳.

흐름:

1. 내용 파일을 고친다.
2. `Backend/`에서 `npm run methods:migration`을 돌린다. 형식이 틀리면 `파일:줄 이유`를 내고 파일을 만들지 않는다.
3. 만들어진 `supabase/migrations/<시각>_study_methods_content.sql`을 확인하고 커밋한다.
4. 개발 프로젝트 반영은 사용자가 요청할 때 `npm run db:push`로 한다. `main`에 병합하면 운영에 자동 반영된다.

이미 배포된 내용 마이그레이션은 고치지 않는다. 내용을 바꾸면 새 마이그레이션을 만든다(파일 하나가 내용 전체를 지우고 다시 넣으므로 여러 개가 쌓여도 마지막 내용이 남는다). 어떤 DB에도 push하지 않은 파일만 지우고 다시 만든다. 개발 DB에 push한 파일을 지우면 다음 `db push`가 이력 불일치로 실패한다.

## 주의

- 내용은 조사 문서에서 옮긴다. [확인]은 그대로 써도 되고, [추정]은 "~하는 편이 안전해요", "~로 보여요"처럼 단정하지 않는 말로 쓴다. [미확인]은 넣지 않는다. 근거가 보도뿐인 제도(시험 시간 110분 등)는 "보도 기준"으로 적는다.
- 날짜는 달("11월~1월") 대신 시험일 기준("시험 6~3개월 전")으로 쓴다. 시험일은 사용자마다 다르다.
- 특정 강사·교재·학원을 추천하지 않는다. 합격수기는 "합격자 사례"로만 쓴다. 사용자가 이미 쓰는 교재(`books`)를 기준으로 제안한다.
- 앱 계획과 어긋나는 말을 하지 않는다. "초반에는 한 과목에 집중"이 아니라 "매일 모든 과목을 계획대로 하고, 약한 과목에 추가 시간"으로 쓴다(`plan-generator`는 매일 모든 교재를 나눠 배정한다).
- 형광펜은 그 과목에서 가장 중요한 원칙·주제에만, 파일마다 최대 3곳.
- 멘탈관리는 [코치 톤 "힘들 때 말하는 방식"](../coach/coach-tone.md#힘들-때-말하는-방식)의 순서(현실 → 방향 → 가능성 → 바로 할 해결책)로 쓴다.
- 건강을 해치는 공부량(밤샘, 수면 줄이기)은 권하지 않는다.
