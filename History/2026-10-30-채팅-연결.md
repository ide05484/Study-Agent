### 고려한 상황과 해결

#### 1. 카카오 키를 어디에 두나

- 상황: 사용자는 플랫폼 키의 REST API 키를 받으면 되는지, 저장소 어디에 넣는지 물었다.
- 해결: REST API 키는 Supabase Kakao provider의 Client ID다. 같은 키 설정 안의 "카카오 로그인 Client Secret"이 Client Secret이다. 로그인은 Supabase가 카카오와 직접 주고받으므로 두 값은 Supabase 대시보드에만 넣는다. 저장소나 `.env.local`에는 넣지 않는다. 카카오톡 발송(알림 단계)에서 함수가 키를 쓰게 되면 그때 `functions/.env`와 `secrets set`을 쓴다.

#### 2. 도메인이 없을 때 카카오 설정

- 상황: 사용자가 Supabase 콜백 URL을 카카오 앱의 "대표 도메인"에 등록했다.
- 해결: 위치가 다르다고 안내했다. 콜백 URL `https://ishtebcswgyagbbaakpx.supabase.co/auth/v1/callback`은 "카카오 로그인 Redirect URI"에 넣어야 한다. 없으면 KOE006이 난다. 대표(사이트) 도메인에는 `http://localhost:5173`을 넣는다. 운영할 때는 Vercel의 `*.vercel.app` 주소를 쓰므로 도메인을 사지 않아도 된다.

#### 3. `.env.local`의 Supabase 키로 Task 1을 할 수 있나

- 상황: 사용자는 Frontend `.env.local`에 넣은 Supabase 키로 진행하면 된다고 봤다.
- 해결: 그 키는 브라우저용 공개 키(URL, publishable key)라 `db push`·`secrets set` 권한이 없다. CLI 로그인(`npx supabase login`, `link`)이 따로 필요하고, 브라우저 인증이라 사용자가 직접 실행해야 한다.

#### 4. 교재를 무엇으로 정하나

- 상황: 해커스 국어·영어는 강사별 기본서가 여러 종류다. 공중보건·보건행정은 "하프모의고사"가 보이지 않고 최성희 실전동형모의고사(2025년판)만 있다. 처음에는 확인 없이 웹 검색부터 하려다가 사용자가 중단하고 "진행하면서 물어봐 달라"고 했다.
- 해결: 검색으로 후보만 모으고 사용자에게 골라 달라고 했다. 국어는 올인원 기본서 + 신민숙 쉬운국어, 영어는 올인원 기본서 + 비비안 하프, 보건 두 과목은 하프 대신 최성희 실전동형을 쓴다. 신민숙 쉬운국어는 5권 시리즈 중 "한 권으로 끝"만 넣었다.
- 남긴 규칙·프로세스: 공부 데이터는 사용자에게 물어가며 채운다(Claude 메모리에 저장).

#### 5. 여러 권 세트와 쪽수

- 상황: 영어 올인원(전3권), 공중보건 기본서(전2권)는 알라딘에 합계 쪽수만 있다.
- 해결: 합계 쪽수로 한 행에 넣는다. 권별로 나눌지는 사용자가 실제 권별 쪽수를 알려 주면 정한다.

#### 6. 어느 계정에 넣나, 다시 실행해도 괜찮나

- 해결: 사용자가 "둘 다"를 골랐다. 지금은 검증용 계정에, 카카오 로그인 뒤에는 그 계정에 같은 SQL을 실행한다. `books`에는 고유 제약이 없어서, 같은 사용자·같은 제목이 있으면 넣지 않는 조건을 SQL에 넣었다. SQL은 일회성 데이터라 저장소 파일로 두지 않고 계획 문서에만 둔다.

#### 7. 교재가 늘어나 기존 확인 문장이 맞지 않음

- 상황: 계획의 완료 확인 문장은 "보건행정 30~70p…"였다. 보건행정 교재가 2권이 되면 교재를 특정할 수 없어서, `parseAnalysis` 규칙(Review Focus 3)에 따라 진도가 오르지 않는다.
- 해결: 확인 문장을 "보건행정 기본서 30~70p…"로 바꿨다. 교재명이 없을 때 진도가 그대로인 것도 같이 확인하도록 Task 6 Step 3에 적었다.

#### 8. 키가 git에 올라가는 템플릿 파일에 들어감

- 상황: 커밋 전에 `git status`를 보니 `Backend/supabase/functions/.env.example`(git 추적 파일)의 `KAKAO_REST_API_KEY`에 값이 들어 있었다. `Frontend/.env.example`은 삭제되어 있었다(`.env.local`로 옮긴 것으로 보임). 커밋되지는 않았다.
- 해결: `.env.example`을 git에 올라가지 않는 `functions/.env`로 복사해 값을 옮겼다(`.gitignore` 확인). 그다음 두 템플릿 파일을 `git restore`로 되돌렸다. `Backend/package.json`의 `@supabase/server` 추가는 사용자 변경이라 그대로 뒀다.
- 남긴 규칙·프로세스: 키 값은 `.env`, `.env.local`에만 넣는다. `.env.example`은 키 이름만 두는 템플릿이다.

## 2026-10-30 Task 1: 개발 프로젝트 연결과 DB 타입 (Native, 진행 중)

### 요청

클라우드 작업은 Supabase MCP로 진행하고 싶다. CLI도 로그인해 두었다. `functions/.env`에 OpenAI 키를 넣었다. OpenAI 키 권한을 무엇으로 줄지, Supabase CLI가 꼭 필요한지도 물었다.

### 한 일

1. **Step 1 (MCP)**: 개발 프로젝트 `Study Agent`(`ishtebcswgyagbbaakpx`, ap-southeast-1, Postgres 17)는 `ACTIVE_HEALTHY`였고, `public` 테이블과 마이그레이션 이력은 비어 있었다. 기본 권한(`pg_default_acl`)상 `public`의 새 테이블은 anon·authenticated에 자동으로 열려서 따로 `GRANT`할 필요가 없었다.
2. **Step 2 ☁️ (MCP, 사용자 승인)**: `apply_migration`으로 초기 스키마를 적용했다. 이력 버전이 적용 시각(`20261030081330`)으로 기록되어 `20261022082116`으로 바꿨다. 테이블 9개 모두 RLS가 켜져 있고 정책이 1개씩 있다. `on_auth_user_created` 트리거도 켜져 있다.
3. 보안 어드바이저가 WARN 2건(anon·authenticated가 `handle_new_user()`를 `/rpc`로 실행 가능)을 냈다. 사용자 승인을 받아 `migration new`로 `20261030081740_revoke_handle_new_user_execute.sql`을 만들고 MCP로 적용했다. 이력 버전도 맞췄다. 다시 확인하니 어드바이저 경고는 0건이었다.
4. **Step 3 ☁️ (CLI, 사용자 승인)**: `OPENAI_API_KEY`, `KAKAO_REST_API_KEY`를 등록했다(`Finished supabase secrets set.`, `secrets list`에 2개). 값은 출력하지 않았고, 임시 파일이 지워진 것을 확인했다.
5. **Step 5**: `gen types --project-id`로 `Frontend/src/interfaces/database.ts`를 만들고 `libs/supabase.ts`를 `createClient<Database>`로 바꿨다.
6. **Step 6**: `npm run build` 성공(청크 500kB 초과 경고만 있음, 기존과 같음), `oxlint` 종료 코드 0. `api/`는 고칠 곳이 없었다.
7. 사용자가 두 `.env.example` 템플릿을 지웠다. 삭제를 유지하기로 해서, LOCAL_DEV.md의 `cp .env.example` 안내를 직접 만들 키 목록으로 바꿨다. MCP로 마이그레이션을 적용할 때 이력 버전을 맞춰야 한다는 내용도 추가했다.
8. 계획 Task 1을 MCP 방식으로 고치고 끝난 Step에 체크했다.

### 고려한 상황과 해결

#### 1. MCP로 마이그레이션을 적용하면 CLI 이력과 어긋남

- 상황: MCP `apply_migration`은 버전을 적용 시각으로 기록한다. 로컬 파일 버전(`20261022082116`)과 다르면, 나중에 CLI `db push`가 같은 파일을 아직 적용하지 않은 것으로 보고 다시 실행하려다 실패한다(타입·테이블 중복).
- 선택지: (a) 이 단계만 CLI `db push`. (b) MCP로 적용하고 이력 버전을 파일에 맞춤. (c) SQL Editor로 실행(이력이 남지 않음).
- 해결: 사용자가 MCP를 원해서 (b). `schema_migrations.version`을 파일 타임스탬프로 바꿨다.
- 남긴 규칙·프로세스: MCP로 마이그레이션을 적용하면 바로 버전을 맞춘다(LOCAL_DEV.md 3절).

#### 2. 비밀 값을 MCP로 등록하면 키가 대화 기록에 남음

- 상황: MCP로 함수 비밀 값을 등록하려면 Claude가 `.env`의 키 값을 읽어 호출에 넣어야 한다.
- 선택지: MCP, 대시보드(사용자가 직접 입력), CLI(파일에서 바로 등록).
- 해결: 세 방법의 차이(키가 거쳐 가는 곳)를 설명했고, 사용자가 CLI를 골랐다. `link` 없이 `--project-ref`로 등록했다.

#### 3. CLI 로그인이 Git Bash에서 읽히지 않음

- 상황: 사용자가 로그인한 뒤에도 Bash 도구에서 실행한 `secrets set`은 `AccessTokenRequiredError`로 실패했다(`gen types`는 성공). PowerShell에서는 `projects list`가 됐다.
- 해결: CLI 명령은 PowerShell로 실행했다. 실패한 시도에서는 등록된 것이 없고, 임시 파일도 지워졌다. 원인(로그인 정보 저장 위치를 셸마다 다르게 읽는 것으로 추정)은 확인하지 않았다.

#### 4. `handle_new_user()` 보안 경고

- 상황: `public`의 함수는 기본으로 anon·authenticated가 실행할 수 있어서, `SECURITY DEFINER`인 트리거 함수가 `/rpc`에 노출된다고 경고가 나왔다. 트리거 함수는 직접 호출하면 Postgres가 거부해서 실제 위험은 낮다.
- 해결: 초기 스키마를 이미 적용했으므로 파일을 고치지 않고 새 마이그레이션으로 `revoke execute`를 했다. 트리거는 실행할 때 EXECUTE 권한을 확인하지 않아서 프로필 자동 생성에는 영향이 없다. Step 4에서 계정을 만들 때 `profiles` 행이 생기는지로 확인한다.

#### 5. OpenAI 키 권한

- 해결: 앱은 Responses API만 쓰므로 Model capabilities(가능하면 그 안의 Responses만)를 Write로, 나머지는 None으로 두라고 안내했다.

### 한 일

1. 모든 브랜치, 커밋하지 않은 파일, 전역 `~/.claude`를 찾아봤다. 컨벤션 문서는 없었다. 규칙은 CLAUDE.md "구조", DESIGN.md "라이브러리·도구"·"컴포넌트 메모", `Frontend/.oxlintrc.json`에 흩어져 있었다.
2. Frontend(api, hooks, interfaces, components, pages, libs), Backend(`plan-generator`, `_shared`), 마이그레이션을 읽고 실제로 쓰는 패턴을 뽑았다. `CONVENTIONS.md`를 만들었다.
   - 다룬 내용: 공통, 이름, Frontend(포맷, 파일, import, TypeScript, api, 훅, 컴포넌트, 스타일, 문구), Backend(포맷, 구조, 함수 작성), DB, Git
3. 코드끼리 방식이 섞인 곳은 **(제안)**으로 기준안을 적었다. "정해야 할 것" 표와 "정리 대상" 목록(파일·줄)으로 모았다.
4. 연결: CLAUDE.md 관련 문서 목록에 추가했다. `code-reviewer`는 CONVENTIONS.md를 스타일 기준 1순위로 보게 했다((제안) 항목은 Minor로만 지적). `implementer`는 시작 전에 읽게 했다.

### 고려한 상황과 해결

#### 1. 섞여 있는 패턴을 어떻게 적나

- 상황: 반환 타입이 있는 훅과 없는 훅이 섞여 있었다. props도 인라인 타입과 `XxxProps`가 섞여 있었다. 오류 문구는 합니다체와 해요체가 섞여 있었다. 120자를 넘는 줄도 있었다.
- 해결: 많이 쓰이거나 더 명확한 쪽을 기준안으로 적고 **(제안)**을 붙였다. 사용자가 확정하면 정리 대상 목록대로 한 번에 고친다. 사용자가 확정하기 전에는 코드를 고치지 않는다.

#### 2. 포매터

- 상황: Frontend는 작은따옴표에 세미콜론이 없다. Backend는 `deno fmt` 형식이다. 둘 다 도구로 강제하지 않는다.
- 해결: Prettier 도입을 "정해야 할 것"에 제안으로만 넣었다. 들이면 전체 파일이 한 번 바뀌므로, 사용자가 정한 뒤 정리 작업과 함께 한다.

### 제안과 결정
