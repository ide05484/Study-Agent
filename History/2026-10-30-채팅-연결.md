### 고려한 상황과 해결

#### 1. 카카오 키를 어디에 두나

- 상황: 사용자는 플랫폼 키의 REST API 키를 받으면 되는지, 저장소 어디에 넣는지 물었다.
- 해결: REST API 키는 Supabase Kakao provider의 Client ID다. 같은 키 설정 안의 "카카오 로그인 Client Secret"이 Client Secret이다. 로그인은 Supabase가 카카오와 직접 주고받으므로 두 값은 Supabase 대시보드에만 넣는다. 저장소나 `.env.local`에는 넣지 않는다. 카카오톡 발송(알림 단계)에서 함수가 키를 쓰게 되면 그때 `functions/.env`와 `secrets set`을 쓴다.

#### 2. 도메인이 없을 때 카카오 설정

- 상황: 사용자가 Supabase 콜백 URL을 카카오 앱의 "대표 도메인"에 등록했다.
- 해결: 위치가 다르다고 안내했다. 콜백 URL `https://ishtebcswgyagbbaakpx.supabase.co/auth/v1/callback`은 "카카오 로그인 Redirect URI"에 넣어야 한다. 없으면 KOE006이 난다. 대표(사이트) 도메인에는 `http://localhost:5173`을 넣는다. 운영할 때는 Vercel의 `*.vercel.app` 주소를 쓰므로 도메인을 사지 않아도 된다.

#### 3. `.env.local`의 Supabase 키로 Task 1을 할 수 있나

- 상황: 사용자는 Frontend `.env.local`에 넣은 Supabase 키로 진행하면 된다고 봤다.
- 해결: 그 키는 브라우저용 공개 키(URL, publishable key)라 `db push`·`secrets set` 권한이 없다. CLI 로그인(`npx supabase login`, `link`)이 따로 필요하고, 브라우저 인증이라 사용자가 직접 실행해야 한다.

#### 4. 교재를 무엇으로 정하나

- 상황: 해커스 국어·영어는 강사별 기본서가 여러 종류다. 공중보건·보건행정은 "하프모의고사"가 보이지 않고 최성희 실전동형모의고사(2025년판)만 있다. 처음에는 확인 없이 웹 검색부터 하려다가 사용자가 중단하고 "진행하면서 물어봐 달라"고 했다.
- 해결: 검색으로 후보만 모으고 사용자에게 골라 달라고 했다. 국어는 올인원 기본서 + 신민숙 쉬운국어, 영어는 올인원 기본서 + 비비안 하프, 보건 두 과목은 하프 대신 최성희 실전동형을 쓴다. 신민숙 쉬운국어는 5권 시리즈 중 "한 권으로 끝"만 넣었다.
- 남긴 규칙·프로세스: 공부 데이터는 사용자에게 물어가며 채운다(Claude 메모리에 저장).

#### 5. 여러 권 세트와 쪽수

- 상황: 영어 올인원(전3권), 공중보건 기본서(전2권)는 알라딘에 합계 쪽수만 있다.
- 해결: 합계 쪽수로 한 행에 넣는다. 권별로 나눌지는 사용자가 실제 권별 쪽수를 알려 주면 정한다.

#### 6. 어느 계정에 넣나, 다시 실행해도 괜찮나

- 해결: 사용자가 "둘 다"를 골랐다. 지금은 검증용 계정에, 카카오 로그인 뒤에는 그 계정에 같은 SQL을 실행한다. `books`에는 고유 제약이 없어서, 같은 사용자·같은 제목이 있으면 넣지 않는 조건을 SQL에 넣었다. SQL은 일회성 데이터라 저장소 파일로 두지 않고 계획 문서에만 둔다.

#### 7. 교재가 늘어나 기존 확인 문장이 맞지 않음

- 상황: 계획의 완료 확인 문장은 "보건행정 30~70p…"였다. 보건행정 교재가 2권이 되면 교재를 특정할 수 없어서, `parseAnalysis` 규칙(Review Focus 3)에 따라 진도가 오르지 않는다.
- 해결: 확인 문장을 "보건행정 기본서 30~70p…"로 바꿨다. 교재명이 없을 때 진도가 그대로인 것도 같이 확인하도록 Task 6 Step 3에 적었다.
