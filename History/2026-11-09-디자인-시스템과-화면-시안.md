# 디자인 시스템과 화면 시안 (Claude 디자인)

- 날짜: 2026-11-09
- 단계: 로드맵 1.5 디자인 시스템 정리, 앞당김
- 관련: 브랜치 `feature/design_system`, [로드맵](../docs/superpowers/plans/2026-10-27-roadmap.md), [DESIGN.md](../DESIGN.md)
  - 결과물: [docs/design/](../docs/design/README.md) (Claude 디자인에서 만든 디자인 시스템과 화면 시안을 파일로 옮긴 것)

## 요청

사용자는 디자인 시스템과, 그것을 적용한 화면 시안까지 보고 싶다고 했다. LLM API를 아직 연결하지 않았고 비용이 부족하니, 디자인을 먼저 하고 API를 연결하는 게 맞겠다고 했다. 색상 토큰과 DESIGN.md 규칙을 바탕으로 하되, 시안이 마음에 들지 않으면 바꿀 수 있다고 했다.

## 한 일

1. Frontend 화면 코드를 모두 읽고 실제 값을 모았다.
   - 읽은 파일: `index.css` 토큰, `classes.ts`, 레이아웃·채팅·대시보드·설정·로그인 컴포넌트
   - 함께 본 문서: DESIGN.md, coach-tone.md
2. Claude 디자인의 Design System 형식으로 "보건직 합격 코치" 디자인 시스템을 만들었다.
   - 토큰
     - 색: 라이트·다크 18개. `index.css` 값 그대로이고, `scrim`을 추가했다.
     - 글자 크기: 8단계(12·14·15·16·16 굵게·17·26·34px)
     - 간격 6개, 모서리 7개, 크기 5개(터치 44px, 헤더 56px, 최대 폭 480px 등)
     - 그림자: 달력 창 하나
   - README: 원칙, 문구, 색상, 타이포, 간격, 레이아웃, 아이콘, 상태와 움직임, 코드와의 연결
   - 컴포넌트 16개. 각각 사용 규칙과 미리보기가 있다.
     - Button, TextField, Marker, Section, AppHeader, Sidebar
     - TodayPlan, ChatBubble, ChatComposer
     - StudyHeatmap, StreakCounter, SubjectProgress
     - DatePicker, Disclosure, KakaoLoginButton, Notice
   - 미리보기는 코드를 보고 다시 그린 정적 화면이다. 공용 스타일은 `components/bundle.css`에 있다. 첫 화면에는 형광펜 띠, 주황 판, 잔디 칸으로 만든 표지를 넣었다.
3. Design 캔버스에 화면 시안 7개(390×844)를 만들었다. 디자인 시스템을 캔버스에 설치했다.
   - 화면: 오늘 채팅, 사이드바 열림, 현재 공부상태, 공부 설정(시험일 달력 열림), 로그인, 지난 채팅(읽기 전용), 오늘 채팅 다크(오늘의 분량 펼침)
   - 화면마다 Tweaks에 다크 모드 스위치가 있다. 로그인 화면에는 실패 문구 스위치도 있다.
   - 화면 사이 링크(사이드바 → 대시보드 등)도 걸었다.
4. 시안을 그리다 달력 창이 좁은 화면에서 넘치는 것을 찾아 코드도 고쳤다(아래 2).
5. 로드맵 순서를 바꿨다. 1.5단계를 1단계 Task 3~7보다 먼저 한다.

## 고려한 상황과 해결

### 1. 지금 디자인을 그대로 옮길지, 새 방향을 제안할지

- 상황: 사용자는 토큰과 DESIGN.md를 바탕으로 하되 시안을 보고 바꿀 수 있다고 했다.
- 해결: 이번에는 지금 코드 값을 그대로 옮긴 기준안을 만들었다. 사용자가 캔버스에서 고치거나 댓글을 달면 그 결과를 DESIGN.md와 코드에 반영한다. 기준안이 있어야 무엇을 바꿨는지 비교할 수 있다.

### 2. 달력 창이 360px 화면에서 넘침

- 상황: 달력 창은 입력 칸 왼쪽(화면 왼쪽에서 약 73px)에서 열린다. 창 안쪽 여백과 테두리 26px까지 더하면, 오전에 정한 폭 `min(18rem, 100vw - 6rem)`으로는 360px 화면에서 오른쪽 여백 안으로 3px쯤 넘친다.
- 해결: `min(18rem, 100vw - 7.5rem)`으로 바꿨다. 390px 화면에서 달력 폭은 270px이다. 디자인 시스템의 `calendar-max` 설명, DatePicker 규칙, `bundle.css`도 같이 고쳤다.

### 3. 코드와 다른 값, 대비가 부족한 값

- 사이드바 딤은 코드에서 토큰이 아니라 `bg-stone-900/40`을 쓴다. 디자인 시스템에는 같은 값의 `scrim` 토큰으로 넣었다.
- 로그인 제목 26px는 DESIGN.md 크기 단계에 없지만 코드에 있어서 `login-title`로 넣었다.
- 달력 창 그림자(`shadow-lg`)는 "그림자를 쓰지 않는다" 원칙의 예외다. `shadow-popover` 하나로만 두고, 원칙에 예외라고 적었다.
- 대비: 라이트의 `accent` 글자는 `bg` 위에서 4.36:1이고, `surface` 위 `text-muted`는 4.2:1이다. 둘 다 작은 글자 기준 4.5:1에 조금 못 미친다. 값은 바꾸지 않고 토큰 설명과 README에 적었다.

### 4. 디자인 시스템 페이지의 자동 저장

- 상황: 달력 폭 수정을 올릴 때 "3분 전에 페이지에서 저장된 버전 위에 파일 3개를 덮어썼다"는 경고가 나왔다(`tokens.json`, `bundle.css`, DatePicker README).
- 확인: 인덱스는 키 순서만 바뀌었고 `lastChange`가 그대로였다. 페이지를 열 때 자동으로 다시 저장한 것으로 보았다. 그 사이 사용자가 페이지에서 고친 것이 있었다면 덮였을 수 있어서, 사용자에게 알렸다.

## 이어서: 햄스터 코치 캐릭터 후보 (같은 날)

### 요청

사용자는 디자인 시스템이 괜찮다고 했다. 이어서 코치 캐릭터를 만들어 로그인, 앱 시작(로딩), 404 화면에 쓰면 어떻겠냐고 했다. 햄스터면 좋겠지만 지금 무드와 어울릴지는 모르겠다고 하며, 레퍼런스 이미지 3장을 주고 후보를 보여 주면 고르겠다고 했다.

### 한 일

1. 레퍼런스의 공통점을 참고했다: 동글동글한 몸, 굵고 부드러운 선, 볼터치, 작은 소품. 레퍼런스 작가의 캐릭터를 옮기지 않고 새로 그렸다.
2. 화면 시안 캔버스에 후보 3종을 추가했다.
   - A 형광이: 굵은 선, 크림 몸에 형광펜 색 머리털, 주황 형광펜을 들고 있다
   - B 합격이: 굵은 선, 웜그레이 얼룩, 주황 필승 머리띠
   - C 해씨: 선 없이 파스텔, 볼에 해바라기씨(오늘의 분량)를 채우고 있다
3. 표정은 네 가지다: 기본, 응원(로그인), 생각 중(앱 시작·로딩), 당황(404). 캐릭터는 부품 하나(`Hamster.dc.html`)를 후보와 표정 값으로 바꿔 그린다.
4. 캔버스에 넣은 것: 후보 비교판 하나, 후보별 적용 화면 3개(로그인 · 시작 · 404).
5. 캐릭터 색은 테마와 상관없이 고정이다. 주황 소품은 `accent`·`marker` 값과 같다.

### 고려한 상황과 해결

- 무드와 어울릴지: 세 후보의 결을 일부러 다르게 했다. A는 앱 콘셉트(형광펜), B는 모노톤 무드, C는 귀여움에 가장 가깝다. 사용자가 비교해서 고르게 했다.
- DESIGN.md "아이콘 대신 이모지를 쓰지 않는다", "장식은 형광펜 하나로 충분하다" 원칙: 캐릭터는 채팅 화면에는 넣지 않았다. 로그인·시작·404처럼 내용이 적은 화면에만 넣었다.

### 남은 일

- (사용자) 후보 고르기, 또는 섞을 부분 알려 주기
- 고른 캐릭터를 디자인 시스템 에셋(SVG)과 DESIGN.md에 넣고, 시작 화면·404 화면을 화면 목록에 추가

### 이어서: B 합격이 선택과 수정

- 사용자가 B 합격이를 골랐다. 다만 선이 너무 굵고 강렬하며, 눈은 흰자가 있는 눈보다 점눈이 낫다고 했다.
- 고친 것
  - 합격이의 선: 굵기 3 → 1.8, 색 `#4a3b33` → `#7a6a60`(연한 웜브라운)
  - 이목구비 선도 가늘게 했다: 눈 웃음선 2.6 → 2.2, 입 2 → 1.7
  - 모든 후보의 눈을 흰자·반짝이 없는 점눈으로 바꿨다. 기본 눈의 흰 반짝이를 없앴고, 당황 표정은 흰자 있는 동그란 눈 대신 점눈 + 땀방울로 바꿨다.
- 남은 일: 사용자가 수정본을 확인하면 합격이를 디자인 시스템 에셋과 DESIGN.md에 넣는다.
- 이어서 사용자가 머리띠가 햄스터 곡률에 맞지 않아 거슬린다고 했다.
  - 원인: 머리띠가 몸 윤곽과 상관없이 따로 그린 납작한 띠였다. 양 끝이 몸 밖으로 삐져나오거나 몸 안에서 끊겼다.
  - 고친 것: 머리 꼭대기 곡선과 같은 방향으로 휜 띠(두께 9)로 다시 그렸다. 몸 윤곽(`ham-body-clip`)으로 잘라서 양 끝이 몸 곡선에 딱 붙는다. 몸 테두리는 머리띠 위에 그려서 경계가 이어진다. 매듭 두 가닥은 띠의 오른쪽 끝(몸 윤곽 위)에서 바깥으로 나오게 옮겼다.

### 이어서: 합격이 확정, 디자인 시스템 반영, 링크 공개 위치

- 요청: 사용자가 합격이로 확정했다. 캐릭터가 들어간 디자인 시스템을 반영하고, 디자인 시스템 링크를 DESIGN.md 등에 넣어 다른 사람이 보기 쉽게 해 달라고 했다.
- 한 일

  - 디자인 시스템에 반영했다.
    - SVG 4장을 에셋(Mascot 그룹)으로 올렸다.
    - Mascot 컴포넌트(미리보기와 사용 규칙)를 추가했다. 컴포넌트는 17개가 됐다.
    - README에 "코치 캐릭터: 합격이" 절을 넣었다.
  - DESIGN.md를 고쳤다.
    - 맨 위에 "디자인 자료" 표를 넣었다(디자인 시스템과 화면 시안 링크).
    - "코치 캐릭터: 합격이" 절을 넣었다: 그림 4장, 쓰는 곳과 크기, 규칙.
  - 루트 README.md를 고쳤다. 맨 위에 합격이 그림과 소개 한 줄을 넣고, 문서 표에 두 링크를 넣었다.
- 고려한 것: claude.ai 아티팩트는 기본이 비공개다. 링크만 넣으면 다른 사람은 열 수 없다. 각 페이지의 Share 메뉴에서 공유해야 하고, 공유 설정은 Claude가 바꿀 수 없다. DESIGN.md에 이 점을 적고 사용자에게 알렸다. GitHub에서 바로 보이도록 합격이 그림은 저장소 SVG로 README와 DESIGN.md에 넣었다.
