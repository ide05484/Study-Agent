# 2.1단계 공부법 채우기: 공부법 DB와 코치 지식

- 날짜: 2026-11-18
- 단계: 로드맵 2.1 공부법 채우기
- 관련: [설계](../docs/superpowers/specs/2026-11-18-study-methods-db-design.md), [조사 문서 원문](../docs/study-methods/research/2026-11-보건직-과목별-공부법.md), [채팅 연결 기록의 다음 작업 피드백 1번](2026-10-30-채팅-연결.md)

## 요청

사용자가 정리한 조사 문서 "보건직 공무원 과목별 공부법"(2027 보건직 기준, 과목별 공부법·시간관리·멘탈관리, 항목마다 [확인]/[추정]/[미확인]과 출처)을 대화에 첨부했다. 이걸로 `docs/study-methods`를 보충하고 DB에 넣어 공부 설정 화면에서 보게 하자고 했다. 목적은 점수가 떨어지거나 힘들어할 때 코치가 코칭할 바탕을 만드는 것이다. 시간관리·멘탈관리는 화면에 따로 두지 않고 물어보면 알려 주는 용도라고 했다.

## 한 일

- 지금 상태를 확인했다. 공부 설정 "과목별 공부법" 탭은 "준비 중" 안내와 비활성 메모 칸뿐이고, 코치 질문 답변(`chat/reply.ts`)에는 공부법이 들어가지 않는다. 로드맵 2.1은 원래 문서 → TS 상수 + 메모 테이블 계획이었다.
- 조사 문서가 길어 질문마다 통째로 넣으면 이미 20~30초 걸리는 답변이 더 느려진다는 점을 먼저 짚었다. 분석 단계가 과목을 뽑으니 해당 과목만 넣자고 제안했다.
- 질문을 하나씩 해 설계를 정하고 [설계 문서](../docs/superpowers/specs/2026-11-18-study-methods-db-design.md)를 썼다. 리뷰어(새 서브에이전트)가 설계만 보고 계획을 세울 수 있는지 확인했다.
- 첨부된 조사 문서를 원문 그대로 [docs/study-methods/research/](../docs/study-methods/research/2026-11-보건직-과목별-공부법.md)에 저장했다(리뷰어가 "원문이 저장소에 없다"고 짚음. 구현 에이전트는 대화를 못 본다).
- 사용자가 설계를 승인했다.

## 고려한 상황과 해결

### 1. DB에 넣는 방법

- 선택지: A. 문서 → 마이그레이션 생성 스크립트 / B. 문서 → DB 동기화 스크립트(비밀 키로 직접) / C. DB 없이 TS 상수(로드맵 원래 안).
- 해결: A(사용자 선택, 추천안). `main` 병합 때 기존 GitHub Actions `db push`가 운영에도 반영해 빠뜨릴 일이 없다. B는 개발·운영에 손으로 돌려야 하고, C는 "DB에 저장"이 아니고 내용만 바꿔도 재배포가 필요하다. 문서를 고칠 때마다 마이그레이션이 하나씩 쌓이는 건 감수한다.

### 2. 메모 칸 대신 채팅에서 배우기

- 상황: 로드맵 2.1에 과목별 메모 테이블이 있었다.
- 해결: 사용자가 메모를 뺐다("수험생이 그걸 쓰며 앉아 있을 것 같지 않다"). 대신 채팅에서 "이렇게 하니 잘 됐다"를 알아듣고 `study_tips`에 저장한다. 바로 저장(추천안)과 확인 후 저장(예/아니오 칩 필요) 중 사용자가 바로 저장을 골랐다. 잘못 저장된 것은 탭에서 지운다. GPT 호출 수는 늘리지 않고 분석 스키마에 칸을 더한다.

### 3. 멘탈관리와 ENTJ

- 상황: 사용자가 공부법 탭에 멘탈관리 아코디언을 더하고, 상대가 ENTJ 성향이라 감정적인 응원보다 방향·현실·가능성·해결책이 꼭 필요하다고 했다.
- 해결: 멘탈관리 문구와 "점수 하락·지침·불안"에 대한 코치 답변을 "현실 → 방향 → 가능성 → 바로 할 행동 → 짧은 응원" 순서로 쓴다. 평소 기록 답변 말투는 그대로. 리뷰어가 "여러 사용자 앱인데 공용 문구에 성향을 고정해도 되나"를 물었고, 사용자는 한 명에게 맞춤으로 쓸 것이니 모두에게 같게 적용하라고 했다. 화면·공부법 문서에는 "ENTJ"라는 말을 쓰지 않고 coach-tone.md에만 이유를 적는다.

### 4. 조사 문서와 앱 규칙의 충돌

- 상황: 조사 문서(영어 18번)의 "초반엔 부담 과목 하나에 집중"은 앱 계획(매일 모든 교재 배정)과 어긋난다. 조사 문서의 날짜(11월~1월)는 6월 시험 가정이다.
- 해결(진행자 판단, 사용자 검토): "매일 모든 과목을 계획대로 조금씩 하고 약한 과목 하나에 추가 시간"으로 바꿔 쓴다. 날짜는 시험일 기준("시험 7~5개월 전")으로 쓴다. [추정]은 단정하지 않는 말로, [미확인]은 넣지 않는다.
