## 2026-11-06 서브에이전트 정의 파일 추가

### 요청

Task 2에서 쓴 구현용·리뷰용 서브에이전트를 `.claude/agents/` 아래 md 파일로 정의해 달라고 했다. 그 전에 서브에이전트 작업 화면을 볼 수 있는지, 어떻게 운영하는지도 물었다.

### 한 일

1. 운영 방식을 설명했다. 진행자(메인 세션)가 Task 지시서를 만들어 구현자에게 맡기고, 구현자가 커밋하면 리뷰어가 지시서와 diff만 보고 판정한다. 지적이 있으면 같은 구현자가 고치고, 리뷰어가 고친 부분만 다시 본다(최대 5회). 작업 화면을 실시간으로 띄우는 방법은 없어서, 지시서·보고서·diff·진행 기록 파일과 원본 기록(JSONL) 위치를 안내했다.
2. Task 2 때 쓴 지시문(superpowers subagent-driven-development 템플릿 + 이 프로젝트 규칙)을 정리해 두 파일로 만들었다.
   - `.claude/agents/implementer.md`: 모델 sonnet, 모든 도구. 지시서대로 구현하고, 확인하고, 지정 경로만 커밋하고, 보고서를 쓴다. ☁️·🔑·브라우저 확인, 계획·History 수정, push, 서브에이전트 호출은 하지 않는다.
   - `.claude/agents/task-reviewer.md`: 모델 sonnet, 도구 Read·Grep·Glob·Bash(읽기 전용으로 씀). 요구사항 충족과 코드 품질을 판정하고, 재리뷰에서는 지적마다 해결 여부를 판정한다.
3. CLAUDE.md "작업 방식"에 두 에이전트를 쓴다는 한 줄을 넣었다.

### 고려한 상황과 해결

#### 1. 템플릿을 그대로 옮길지, 프로젝트 규칙을 넣을지

- 상황: superpowers 템플릿은 영어이고 프로젝트를 모른다. Task 2 때는 dispatch 메시지에 프로젝트 규칙(의존 방향, 토큰, 커밋 규칙, 사용자 변경 제외)을 매번 붙였다.
- 해결: 매번 붙이던 규칙을 정의 파일 본문에 넣었다. dispatch 메시지에는 지시서·보고서 경로와 그 Task의 결정만 넣으면 된다. 문서 규칙에 맞춰 한국어로 썼다.

#### 2. 리뷰어의 쓰기 권한

- 상황: 리뷰어는 `git diff`가 필요해서 Bash를 빼기 어렵다. Bash가 있으면 작업 트리를 바꿀 수도 있다.
- 해결: 도구는 Read·Grep·Glob·Bash로 줄였다(Edit·Write 없음). Bash로 바꾸는 명령은 본문에서 금지했다.

### 고려한 상황과 해결

#### 1. 줄바꿈(CRLF/LF)

- 상황: 이 PC는 `core.autocrlf=true`라 작업 트리 파일이 CRLF다. Prettier 기본값(LF)으로 포맷하자, 내용은 같고 줄바꿈만 다른 파일 5개가 modified로 남았다. CRLF로 체크아웃한 곳에서는 `format:check`가 실패할 수 있다.
- 선택지: `.prettierrc`에 `endOfLine: "auto"`, 또는 `.gitattributes`로 저장소 전체를 LF로 고정.
- 해결: `endOfLine: "auto"`. 저장소 전체 줄바꿈 정책을 바꾸지 않는 가장 작은 변경이다. 줄바꿈만 다른 5개 파일은 `--ignore-cr-at-eol` diff가 비어 있는 것을 확인하고 되돌렸다.

#### 2. 120자를 넘는 줄

- 상황: 포맷 뒤에도 5줄이 120자를 넘었다(Sidebar, ChatPage, LoginPage 2줄, SettingsPage). 모두 className 또는 SVG path 문자열이다.
- 해결: 클래스 문자열을 이어 붙이지 않는 규칙(3.8)이 우선이라 그대로 두고, 3.1에 예외로 적었다. 구현자가 짚은 점: awk는 한글을 바이트로 세서 실제보다 길게 나온다. node로 글자 수를 셌다.

#### 3. `as unknown as` 주석이 틀림

- 상황: 구현자가 "supabase-js가 조인을 배열로 추론한다"는 이유 주석을 달았다. task-reviewer는 이 주장을 확인하지 못했다고 남겼다. 진행자가 `database.ts`를 보니 `daily_tasks.book_id → books`는 다대일 관계라 단일 객체로 추론되는 관계였다.
- 해결: 수정 1차에서 `as DailyTaskWithBook[]`로 바꿨고 tsc가 통과했다. 틀린 주석과 `unknown`을 지웠다. Task 1에서 `createClient<Database>`로 타입을 붙인 뒤로는 필요 없어진 캐스트였다.

#### 4. 리뷰 Minor를 이번에 고친 이유

- 상황: code-reviewer가 Minor 3건을 냈다.
  - `useKakaoLogin.error`가 boolean이라 3.6의 `string | null`과 다르다.
  - 로그아웃 진행 표시가 없다.
  - 사이드바를 닫았다 열면 지난 오류가 남는다.
- 해결: 이번 작업의 목적이 컨벤션 정리라서, 같은 파일 안의 규칙 불일치를 남기지 않으려고 같이 고쳤다.
  - `KakaoLoginState`, `SignOutState` 인터페이스를 두었다.
  - `signingOut` 동안 버튼을 비활성으로 했다.
  - 사이드바가 닫히면 `clearError()`를 부른다. 다시 열 때 숨기는 방식은 상태가 남아 다시 보이므로 고르지 않았다.
- 남은 메모(Minor): 두 훅의 catch에 `console.error(e)`가 들어갔다. 원인을 삼키지 않으려는 것이고 화면에는 고정 문구만 보인다. LoginPage는 훅의 `error` 문구 대신 같은 문구를 직접 적어 둔다. URL 오류와 문구를 합칠 때 정리할 수 있다.
